# ROS 使用约定

通过公开 ROS 接口开发和调用能力。任务原则见 `AGENTS.md`，适配流程见 `.agents/skills/setup-body/SKILL.md`。

- **优先复用接口。** 连续状态用 Topic，快速请求用 Service，需要反馈和取消的操作用 Action。能力负责可复用的感知、计算、规划和控制，任务编排与跨步骤决策留在会话中。
- **优先使用 ROS 2 CLI。** 用 `ros2` 命令发现、查询和调用接口；缺能力时开发节点并封装公开 ROS 接口。持续订阅、动作跟踪或取消需要常驻通信时，可复用 `agenticros-ros`，用法见适配技能。无论使用哪种客户端，都须保留请求标识、反馈、取消和状态核对。
- **核对身份和观测。** 端点固定为 `/robot/<robot_id>/...`，session 放在消息中；按机器人隔离能力、证据和坐标系，session 改变后清除旧观测并重新核对。分别判断进程、发现、RPC、数据新鲜度和控制状态。通过原生传感器话题取图，配对图像、CameraInfo 和采集时刻的 TF；状态更新时间不代表图像采集时间。
- **检查运动条件。** 发送前确认实测状态、忙碌或恢复状态、单位、坐标系、自由度、限制、障碍净空及取消方式。拒绝非有限值、超限、不支持或已知不可达的目标；未知可达性通过计算或分阶段试验确认。
- **每个动作只发送一次。** 记录 UUID 并携带当前 session。接受或结果超时（包括 `outcome=unknown`）后查询原动作，不重发；换 session 后查不到旧回执，也不证明动作没执行。取消后取得终态回执并核对实测停止；客户端退出、发现离线或子 agent 中断均不代表停止。不确定时暂停该臂后续动作，继续可行的观测和诊断。
- **保留执行证据。** 记录 session、UUID、完成情况、执行程度（`none/some/unknown`）、停止确认、实测状态和原因。关键阶段重新观测；伺服完成不等于抓取或任务成功。
- **保持工作区清晰。** `/workspace/robot_docs/` 是按型号分类的只读公开资料，使用前核对型号和版本；代码与公开接口源码放在 `ros_ws/src/` 并在 `ros_ws` 内构建，观测、回执和日志放在 `evidence/`。所有路径均相对 `/workspace`。
- **管理自己的节点。** 启动前检查是否已有实例，记录构建、启停、健康检查方法和日志，只停止自己管理的节点。沿用同一 `ROS_DOMAIN_ID` 和原生 DDS 自动发现，不另设注册服务或控制租约。退出或重启前确认相关动作已停止，重启后不得自动运动或重放目标；新接口的客户端重载方法见适配技能。
- **按证据登记能力。** 将能力及生成节点记入 `capabilities/manifest.json`，字段格式见 `.agents/skills/setup-body/SKILL.md` 的“能力清单格式”章节。未验证能力可以继续开发和分阶段试验；验收只检查清单、证据和在线接口，不证明功能、停止状态或任务成功，也不代替实时观测。
