name: setup-body
description: 适配未知 ROS 2 环境或补充缺失能力时使用；发现并验证已有接口，按需开发功能节点，建立供 Codex 逐步调用的能力清单。
---

先读 `/workspace/contract.md`，按其执行保障与能力清单格式工作。环境专用接口和说明未预装。

1. 用 ROS 2 工具发现节点、topic、service、action、类型和 QoS；查看参数及公开说明，建立单位、限制、几何和控制语义，不凭名称猜测。
2. 标准类型可直接使用。自定义类型需找到环境公开定义，检查后在 `/workspace/ros_ws/src/` 保存并构建。ROS 图能发现类型名，不意味着 Humble 自动安装了绑定；缺少定义或关键语义时继续查公开资料及接口，只有无法取得必要信息时才报告具体阻塞及查找证据。
3. 验证已有能力；确有缺口时主动扩展或新建最小可用 ROS 节点。允许临时计算与脚本用于算法探索和调试，持续使用的能力再沉淀到节点。缺模型时探索公开资料、传感观测、标定及小幅仿真探测，不把缺少完整模型作为自动停止条件。
4. 构建并启动需要的节点，保存源码、overlay 加载方式、启停及健康检查命令、进程标识和日志。确认节点在终端命令结束后仍运行，并通过 ROS 接口验证；启动不自动运动。
5. 运动验证前建立实时身份、状态、观测以及 UUID、会话、取消和停止核对机制。实际查看图像，再从设备支持的小幅、分段运动开始试验；保留请求、回执和观测证据，不能从动作完成推断抓取成功。用户已授权的仿真任务无需逐次请示；新能力可以先用于开发验证，失败后核对状态、修正方法并继续。
6. 写入 `/workspace/capabilities/manifest.json`，区分已验证和未验证能力，注明接口来源、调用方法、证据与限制。直接复用环境接口是有效适配，不必为验收编写多余节点。
7. 只报告已验证能力就绪；重新观测后回到“大脑”职责，通过 ROS 命令逐步编排任务。后续阶段仍有能力缺口时继续开发，不在完成发现或更新清单后提前结束用户的任务。

复用已验证的能力和节点。重启或换会话后重新核对身份、状态与观测，清单不代表当前在线状态。
